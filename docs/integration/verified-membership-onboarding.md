## Public RPCs

Use authenticated Supabase PostgREST POST requests (never a service key). All inputs required, no defaults. Verified current platform admin only; generic 42501 denial. Unknown/malformed API type coercion can fail before entry. Unexpected errors/transport loss mean outcome unknown; do not display raw DB errors. Normal domain outcomes are HTTP 200; inspect status.

| RPC | Arguments |
| --- | --- |
| prepare_org_member_assignment | p_organization_id uuid, p_email text, p_role text |
| assign_verified_org_member | p_organization_id uuid, p_email text, p_role text, p_request_id uuid, p_intent_token text |
| update_org_member | p_organization_id uuid, p_user_id uuid, p_role text, p_active boolean, p_expected_revision bigint |

Roles exactly staff or leader. Preparation validates only input and administrator, performs no target/org/member lookup, creates no durable reservation. Output keys status, request_id, intent_token, execute_before, replay_before; status intent_issued, invalid_input or busy; other fields null on non-issuance. Deadlines UTC ISO timestamps. No key provisioned by migration; missing key fails closed.

Assignment/update response keys status, membership (null or organization_id, user_id, role, active, revision), replayed, retry_after_seconds. Revision JSON is a decimal string; read current membership revision safely (text projection or checked safe integer), send bigint argument losslessly. Existing membership SELECT and RLS preserved. Assigned and already_member have snapshot; updated, unchanged, state_conflict have current/new snapshot. Other statuses null. retry_after_seconds is positive only for rate_limited. No account email, provider/student data, candidate count or raw failure exposed.

Assignment statuses: assigned, already_member (conflict, never overwrite/reactivate), account_unavailable (absent/unconfirmed/ambiguous), organization_unavailable (missing/inactive), invalid_input, request_mismatch, request_expired, rate_limited, busy. Known-key syntactically valid MAC mismatch is generic request_mismatch (including actor/payload tamper); unknown key/malformed invalid_input. No membership details for unavailable/invalid. Case-insensitive ASCII exact email, outer space/tab/CR/LF trimmed, dot-atom local <=64 bytes and normalized total <=254, exact hnu.edu.ph; no alias/wildcards/fuzzy search. Count all normalized matches including SSO/unconfirmed; selected original row must meet authoritative confirmed/domain gate. No user metadata or student binding.

Update statuses: updated, unchanged, state_conflict, membership_unavailable, account_unavailable, organization_unavailable, invalid_input, rate_limited, busy. Revision starts at 1 and bumps once for each actual change; original granted_by immutable. No-op not proof of eligibility. Role change (even inactive), reactivation, combined role+deactivation require verified unique target and active org. Same-role pure deactivation does not require target verification/lookup or active organization and is exempt from lookup budget. Stale revision returns state_conflict, no automatic overwrite or refresh-and-retry. No insert/upsert/delete through update.

## Identity and concurrency guarantee

Actual READ COMMITTED, volatile functions, 2s statement/250ms lock timeout, NOWAIT selected Auth/admin/org/membership locks where applicable. Admission row serializes same actor. Selected actor/target rows locked in deterministic UUID order; current admin rechecked, org active and revision checked. Tentative write then one final fresh statement snapshot verifies exactly one normalized match and same confirmed UUID; failure rolls back inner mutation, returns generic unavailable. Composite PK prevents duplicates. No routine table-wide Auth lock or managed Auth DDL. Independent Auth writer can insert a new matching row after final verification snapshot but before commit: accepted synthetic residual phantom window, **not strict commit-time global uniqueness**. Existing access checks are not a retrospective global-uniqueness check. Preserve old memberships even if currently unverified; no cleanup, no automatic grants, no change to student/event/staff/attendance/coverage. Session revocation semantics remain existing row-based identity authority.

## Signed intents and retry

Server request UUID and signed v1 token (dot-delimited ASCII version, audience, key UUID, request UUID, issue/execute/replay epoch seconds, 64 lowercase hex MAC). MAC is HMAC-SHA256 over UTF-8 PG17 JSONB array text in order [version,audience,key_uuid,actor_uuid,request_uuid,issued_at,execute_before,replay_before,org_uuid,normalized_email,role]. No email/org/role/actor plaintext in token; never log tokens or input bodies. Fresh CSPRNG 32-byte blinding key per tag comparison, HMAC both 32-byte tags under same independent key, compare only blinded outputs; fail closed on crypto error. [Actual prerequisite](https://github.com/HNU-Falcon-Devs/hnu-dash-backend/actions/runs/45986154176/job/140462181464) supports functional synthetic mitigation, NOT proof of constant time or production security.

New execution strictly before issued+300s; replay strictly before issued+2592000s; authoritative server clock. Same actor, UUID and exact normalized payload bound even if previous attempt never committed. Verify token and current admin before historical response; no fresh lookup on recorded replay, no new quota/write. Same UUID changed payload never returns success. If no receipt and execution expires, request_expired; after replay expiry never execute even if purged. Rate-limited calls have no receipt; retry same token within execution window. Definitive rejected/busy receipt is terminal; deliberate retry uses new preparation. Unknown transport outcome: reuse exact token/UUID, not new intent. Historical replay is not current entitlement; refresh list. Lost token/reload/expiry: reconcile with authorized operator, then explicitly confirm a new intent. A valid unexecuted intent resolves current account at execution, not at preparation. No localStorage, URL, analytics or persistent browser cache.

## Restricted operations and retention (synthetic only)

Private schema membership_private contains signing_keys, operation_audit, rate_state and helpers; no Data API exposure, no client access even platform admin. Existing privileged database operator/definer context is trusted; no new Auth privileges granted. No new service or generic audit platform. Mutation and audit receipt commit atomically. Expected business failures persist admitted attempt; unexpected abort, cancellation, invalid gateway coercion and unauthorized raised denial cannot be guaranteed durable. Known contention inner rollback may record busy; admission/authority contention can roll back whole call. No raw failed email/hash, keys/MAC/token, candidate IDs for unavailable, or student records stored. Historical successful/conflict receipt snapshots and original grantor remain restricted.

Shared actor-wide 10 admitted attempts/rolling 60 seconds across organizations and verification-required updates; count invalid/new attempts, not valid receipt replay, no lookup before budget. Pure same-role deactivation exempt; no-op/stale exempt responses and over-limit requests aggregate per actor/minute, not unbounded per-call records. Preparation is stateless/no lookup, no budget; residual CPU/traffic exposure not DDoS guarantee. Audit mutation 365 days; nonmutation/receipt/summary 30 days from admission (never earlier than signed replay expiry); idle rate state 30 days. Restricted operator can run membership_private.prune_telemetry(limit 1..1000) in bounded transactions; no scheduler enabled. Restricted backup retention and actual institutional policy separate. Monitor/approve cleanup before enabling it. Operators must not alter audit except authorized maintenance; privileged DB owner is trusted and not an application API.

No production key provision. In authorized disposable synthetic DB only, operator may insert a freshly generated extensions.gen_random_bytes(32) directly into membership_private.signing_keys with unique deployment/epoch audience, signing=true, verify_until NULL; never return/log/export secret. Rotate atomically: mark old signing=false, verify_until no earlier than last issued replay deadline (normally rotation time +30 days), insert new active key with fresh UUID/material; revoke compromised key immediately (delete), manual reconciliation. Do not reuse environment/restore epoch. On restore or known clock rollback halt writes, invalidate pre-restore keys before resuming; no automatic recovery claim. Production secret storage/privileges, RNG/side-channel review, Auth identity invariant, OAuth/SSO and logging/backup/restore readiness remain gated. No real key, real data or production mutation authorized.
